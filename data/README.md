# Data

The corpus is **not committed** to this repository. It is roughly 94 MB, it is third-party
material, and redistributing the full text of tweets is inconsistent with both the Kaggle
listing's terms and the X/Twitter Developer Agreement, which permits redistribution of tweet
identifiers but not of hydrated content. Nothing in the analysis is lost by this: the notebook
reads the file from disk and every number it reports is recorded in `docs/run_log.md`.

## What the notebook expects

Only two columns are read: `date` and `text`. Timestamps carry no timezone marker and are
verified as UTC; §2 parses them with an explicit UTC declaration and converts using the named
`Asia/Tokyo` zone rather than by adding a fixed offset.

## Properties that matter for interpretation

| Property | Value |
| --- | --- |
| Records as supplied | 312,791 |
| Documents after cleaning | 261,467 |
| Calendar span | 25 July – 8 August 2021 (15 days) |
| Dates actually collected | 9 |
| Dates absent | 2–7 August 2021 |
| Hours collected per date | 3 to 16, not uniform |

Two consequences are handled in code rather than in prose.

**Collection is incomplete and uneven.** Absolute daily counts are not comparable across dates,
so §10 uses relative prevalence P(k,d) = n(k,d)/N(d). Uncollected dates are `NaN`, not zero: a
date that was never sampled is unknown, not empty.

**25 July is a 3-document stub.** Only three hours were collected and only two gymnastics
documents survive cleaning. §10 therefore also returns `NaN` for any date with fewer than 30
gymnastics documents, because too few observations cannot establish absence. §17.1 shows that
thresholds of 10, 20, 30 and 50 all exclude exactly this one date and nothing else, so the
exclusion follows from the structure of the collection rather than from the value chosen.

**The window opens too late.** Collection begins on 25 July, after the discourse of interest was
already underway. This is the project's principal limitation and the reason RQ3 yields no valid
estimate. It is a property of the data, not of the method.

## Google Trends

The external series is fetched at run time through `pytrends` (worldwide, `en-US`, daily) and
cached under `cache/`, keyed by query, window and geography. The cache is what makes the reported
numbers reproducible: Google Trends normalises each series to the maximum of the *requested*
window, so the same query over a different window returns different values. Topic 40 is specified
as the Google Trends entity `/g/11h582cpmh` rather than the search term "peacock", because the
term is dominated by the bird.

## The labelled coding sheet

`outputs/coding_sheet.csv` holds two coders' independent labels over 150 documents and is also
not committed, for the same redistribution reason — it contains full tweet text. It is the only
artefact in the project that cannot be regenerated by running code, so the cell that creates the
blank instrument is deliberately disabled in §16. Keep a backup outside the repository. §16
prints `Coding not yet complete.` and continues when the sheet is absent.
