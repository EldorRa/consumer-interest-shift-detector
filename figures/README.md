# Figures

Two sets of figures exist in this project and they should not be confused.

## Analysis figures

Sixteen, embedded in `notebooks/consumer_interest_pipeline.ipynb` and visible in
`docs/executed_notebook.html`. The largest group is the eight paired plots from §13.2: relative
topic prevalence in the upper panel, relative search interest in the lower, with the Google
Trends baseline period shaded so that it is obvious the baseline precedes the Twitter observation
window. These are evidence, and they live inside the notebook that produced them.

## Report figures

Six, generated by `make_figures.py` and committed here as PDF. **They are named by their number
in the report**, so `fig3_models.pdf` is Figure 3. Figure 1 is the framework diagram, drawn by
hand and not produced here.

| File | Report | Shows |
| --- | --- | --- |
| `fig2_coverage.pdf` | Figure 2 | Daily document volume. Bars are documents per date, shaded bands mark dates not collected, annotations give hours collected |
| `fig3_models.pdf` | Figure 3 | Model comparison on three criteria. Coherence is plotted as its absolute value, so shorter is better there; for diversity and seed consistency longer is better, and each panel is annotated with its direction |
| `fig4_prevalence.pdf` | Figure 4 | Relative prevalence of the eight candidate topics. Series break at uncollected dates rather than falling to zero; the qualifying topic is emphasised |
| `fig5_disagreements.pdf` | Figure 5 | The nineteen coding disagreements, by label pair and by topic |
| `fig6_paired.pdf` | Figure 6 | Relative prevalence against relative search interest for the qualifying topic, with the Trends baseline period shaded |
| `fig7_detectability.pdf` | Figure 7 | Days between retrospective appearance and prospective detectability, per candidate |

## Regenerating

```bash
python figures/make_figures.py          # PDF, the format the report uses
python figures/make_figures.py --png    # also PNG, for previewing
```

PDF is deliberate. Vector output stays sharp at any zoom, embeds text that remains searchable
and selectable (`pdf.fonttype = 42`), and keeps the file small. `pdflatex` includes PDF natively,
so the report references them without an extension:

```latex
\includegraphics[width=\linewidth]{figures/fig3_models}
```

## Design rules

Every value is read from `outputs/`. No number is copied from the report into this script, so a
figure cannot disagree with the artefact it is drawn from.

| | |
| --- | --- |
| Input | `outputs/*.csv` only |
| Output | PDF, 300 dpi fallback raster, text embedded as text |
| Colour | one accent (`#2563eb`) against grey; no colour carries meaning alone |
| Missing data | gaps left as gaps |

That last rule is the one that matters. A collection gap is not a zero, and a figure must not
imply it is. The defect that produced a false emergence for every topic in an earlier version of
the analysis was this mistake made in code rather than in a plot, and it is recorded in
`docs/decisions.md`.

## Two artefacts the notebook must write first

`make_figures.py` reads only from `outputs/`, so the daily coverage counts and the Trends series
have to be saved there rather than left in the notebook's memory:

- `outputs/daily_coverage.csv` — written at the end of §2
- `outputs/trends_series.csv` — written at the end of §13

Without them, Figures 2 and 6 cannot be regenerated from a clean checkout.

`fig5_disagreements.pdf` additionally needs `outputs/coding_sheet.csv`, which is excluded from
version control because it contains full tweet text. The script skips that figure and continues
when the sheet is absent, so a reviewer without it still regenerates the other five.
